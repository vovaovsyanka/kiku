# Архитектура Кику

## Поток одной реплики (голосовой режим)

1. `MicListener.listen()` открывает микрофон, Silero VAD вырезает фразу (с запасом 320 мс до начала речи).
2. `WhisperASR.transcribe()` превращает фразу в текст; галлюцинации на тишине («Субтитры…») отфильтровываются.
3. `split_wake()` ищет «Кику» в первых трёх словах или в последнем. Нет имени и окно разговора закрыто — реплика игнорируется.
4. `Agent.respond()`:
   * **быстрый путь:** `Router.try_route()` узнаёт типовые команды (открыть папку/приложение, окна, громкость, время, задачи)
     и выполняет их шаблоном без LLM;
   * иначе собирает системный промпт (характер, каталог инструментов, факты из памяти; без времени, чтобы llama.cpp
     переиспользовал уже обработанное начало промпта), время добавляется к сообщению хозяина;
   * просит LLM вернуть JSON `{actions: [{tool, args}…], say}` (грамматика гарантирует форму, `enum` — имена инструментов);
   * `say` сразу уходит в TTS, действия выполняются через `ToolRegistry.call()`;
   * второй вызов LLM — только если какому-то действию нужен результат (`reads=True`) или оно завершилось ошибкой;
   * защита от зацикливания: повтор того же вызова прерывает цикл.
5. `QwenTTS.speak()` синтезирует реплику целиком (длинную — крупными частями) и играет одним куском; готовые фразы кэшируются в `data/tts_cache`.
6. Пока Кику говорит, микрофон закрыт (полудуплекс).

## Модули и точки расширения

| Нужно | Где менять |
|---|---|
| Другая LLM / другой движок | `kiku/llm/`: реализуйте `chat_json(messages, schema)` и добавьте ветку в `build_llm` |
| Новый инструмент | `kiku/tools/` (см. README) |
| Характер, правила, примеры | `kiku/persona.py` |
| Другой ASR / TTS | `kiku/voice/asr.py`, `tts.py` — интерфейсы `transcribe(audio)` и `speak(text)/wait()/stop()` |
| Хранилище памяти | `kiku/memory/store.py` (сейчас SQLite + FTS5; векторный поиск добавляется рядом) |

## Память

* `notes` (kind=`fact`) — последние N фактов подставляются в системный промпт каждой реплики.
* `notes` (kind=`note`) — доступны через `recall`.
* `tasks` — задачи со сроком; `list_tasks` сортирует по сроку.
* `files` — индекс имён файлов и названий папок. Русская морфология — грубый «стемминг» по окончаниям + префиксный поиск,
  поэтому «конспекты» находит «конспект». Это не семантический поиск; для него позже добавим эмбеддинги (bge-m3).

## Что взято из изученных проектов

**Статья на Хабре (habr.com/ru/articles/891270)** — агент, управляющий компьютером через скриншоты и JSON-команды.
Взято: JSON-команды от модели, индикатор состояния («слушаю / анализирую / выполняю / ожидаю»), итеративная проверка результата,
принцип «клавиатура прежде всего» (для будущего управления GUI). Не взято: облачная LLM (OpenRouter/Gemini),
цикл «скриншот → модель» для каждой команды: для вашей задачи это медленно и ненадёжно на локальной модели.
Автор сам называет проект далёким от реального использования.

**Open-LLM-VTuber** — зрелый проект: Live2D-аватар, голосовое перебивание без наушников, офлайн-режим,
режим «питомец на рабочем столе», отображение «мыслей», реакции на касания, много движков ASR/TTS/LLM.
Минусы для ваших требований: большая часть LLM-интеграций идёт через внешние серверы (Ollama, LM Studio и т.п.),
среди перечисленных TTS нет Qwen3-TTS, долговременная память временно убрана, ветка v1 в режиме поддержки,
ведётся переписывание v2. Есть интерфейс `Agent`, куда можно встроить своего агента.
Live2D-модели из примеров идут под отдельной лицензией Live2D.

## Аватар — варианты

1. **Свой веб-аватар на нашем протоколе событий (рекомендую).** `ui/web.py` уже шлёт `state/say/tool`.
   Добавляем на страницу Live2D (через pixi-live2d-display) или VRM (three-vrm), связываем `speaking` с движением рта
   (громкость TTS-аудио), `say` с эмоциями. Минимум чужого кода, полный контроль, офлайн.
2. **Взять фронтенд Open-LLM-VTuber (репозиторий Open-LLM-VTuber-Web) и научить его говорить с нашим бэкендом.**
   Быстрее получить красивый результат, но нужно реализовать их WebSocket-протокол (я его не изучал) и привязаться к их версии.
3. **Встроить Кику в Open-LLM-VTuber как свой Agent.** Быстрее всего получить аватар и перебивание голосом,
   но вы получите чужой стек для ASR/TTS и потеряете часть контроля над безопасностью.
