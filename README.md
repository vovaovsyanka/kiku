# Кику — локальная голосовая помощница-горничная для ПК

Полностью локальный голосовой ассистент для Windows: слышит вас, понимает русский, управляет папками,
файлами и приложениями, помнит задачи и факты о вас, отвечает голосом.
Никаких облачных API, никаких внешних серверов моделей: всё работает внутри одного Python-процесса,
модели скачиваются с Hugging Face один раз и дальше лежат в `./models`.

> Статус: **v0.1 (каркас)**. Логика ядра покрыта тестами (`python -m unittest discover -s tests -v`),
> но сами нейросети в разработке не запускались. Первый запуск на вашем железе — это проверка.
> Что именно не проверено — см. раздел «Известные риски».

## Что умеет сейчас

«Быстрые» команды выполняются шаблонами за доли секунды, без языковой модели. Всё остальное понимает LLM.

| Область | Примеры фраз | Как работает |
|---|---|---|
| Папки | «открой загрузки», «открой документы/учёба», «что лежит на рабочем столе?» | быстро / LLM |
| Файлы | «создай файл заметки.txt на рабочем столе с текстом привет», «создай папку Проекты» | LLM |
| Приложения | «запусти кс», «открой блокнот» (только белый список `apps`) | быстро |
| Окна | «сверни вс код», «разверни хром», «переключись на телеграм», «сверни все окна», «какие окна открыты?», «закрой телеграм» (с подтверждением) | быстро / LLM |
| Звук и медиа | «громче», «тише», «без звука», «пауза», «следующий трек» | быстро |
| Система | «который час», «заблокируй компьютер» (с подтверждением) | быстро / LLM |
| Задачи | «добавь задачу сдать курсовую до двадцатого октября», «какие у меня задачи», «отметь первую выполненной» | быстро (список) / LLM |
| Память | «запомни, что я пью зелёный чай», «что я говорил про чай?», «забудь это» (с подтверждением) | LLM |
| Поиск файлов | «проиндексируй мои папки», «где лежит конспект по линейной алгебре?», «открой его» | LLM |
| Чтение файлов | «прочитай мою заметку на рабочем столе» (только текстовые файлы: txt, md, csv, json, py…, первые 4000 символов) | LLM |

**Пока не умеет** (нет инструментов, это не «ограничение системы»): печатать текст и нажимать кнопки в чужих программах,
видеть экран, читать PDF/Word и бинарные файлы, открывать сайты и искать в интернете, управлять яркостью, Wi-Fi и питанием,
закрывать процессы, работать с буфером обмена, напоминать по времени (задачи пока хранятся, но не «звонят»),
отвечать на вопросы о событиях после даты обучения модели. Если просьба вне списка, Кику должна прямо сказать, что этого не умеет.

Индекс поиска хранит только **имена** файлов и папок. Содержимое она читает лишь по прямой просьбе и только текстовые файлы;
после чтения файла Кику может только отвечать, а не менять систему (защита от «приказов» внутри файла, см. «Безопасность»).

## Окно с Кику и Kiku.exe

`python -m kiku gui` открывает окно: по центру Кику, сверху текст её ответа, снизу распознанная вами фраза,
внизу строка для команд текстом.

| Что происходит | Поза Кику |
|---|---|
| ждёт | стоит и улыбается (слегка «дышит») |
| слышит речь (любую, пока вы говорите и пока идёт распознавание) | рука у уха |
| выполняет команду, ждёт ответ модели и озвучку | задумалась |
| звучит её голос | говорит (покачивается в такт) |

Фразы без имени «Кику» тоже показываются внизу серым с пометкой «(не мне)», но Кику на них не отвечает (если не идёт
окно диалога). Модели грузятся в фоне, окно появляется сразу. Если голос или микрофон не загрузились, окно работает
как текстовый чат. Лог пишется в `data/kiku.log` (в окне консоли нет).

**Kiku.exe — без консоли.** Запустите `build_exe.bat` (один раз): он соберёт маленький `Kiku.exe` и положит его в корень
проекта. Двойной щелчок по нему запускает окно; ярлык на рабочий стол: ПКМ — Отправить — Рабочий стол.
Это лаунчер, а не «всё в одном exe»: он находит в проекте виртуальное окружение (`kikuenv`, `.venv`, `venv`) и запускает
там `pythonw -m kiku gui`. Поэтому папка проекта, окружение и `models` должны оставаться на месте, а exe нельзя просто
копировать на другой компьютер. Нестандартное окружение — впишите путь к `pythonw.exe` в `launcher.txt`.
Без сборки можно так же запускать `launcher.pyw` двойным щелчком. Полноценный автономный exe со всеми моделями —
отдельная задача (многие гигабайты, хрупкая упаковка CUDA); пока не делали.

Свои картинки: положите лист 2x2 (с прозрачным фоном) в `kiku/ui/assets/source_sheet.png` и выполните
`pip install scipy` и `python scripts/make_assets.py`.

## Скорость: замеры и решения

Лог вашего запуска (RTX 3050 Laptop, LLM на CPU) показал:

| Этап | Измерено | Вывод |
|---|---|---|
| Распознавание (Whisper на GPU) | 1–4 с | не узкое место |
| LLM (Qwen3-30B-A3B, CPU) | 5–6 ток/с; первый вызов 32 с | генерация медленная; первый вызов оплачивал разбор промпта |
| TTS (Qwen3-TTS 0.6B) | RTF 2.5: секунда звука = 2.5 секунды ожидания | главный тормоз: 10–60 с на ответ |

Что сделано: (1) в озвучку идёт только начало ответа (до 160 символов, целые предложения), а на экране показан весь текст;
модель просят отвечать одним коротким предложением, это сокращает и генерацию, и озвучку; (2) при старте модель «прогревается»,
чтобы первая команда не ждала разбора промпта; (3) готовые фразы кэшируются на диск, а в простое типовые («Делаю громче»,
«Запускаю Counter-Strike», «Да, слушаю») синтезируются заранее; (4) типовые команды идут мимо LLM (router).

Чего пока **не** делали, и почему: потоковая передача ответа LLM в озвучку (даст выигрыш, но усложняет код, а при RTF 2.5
выигрыш ограничен) и замена голосовой модели. Решать лучше по данным: `python scripts/bench_tts.py` сравнит bfloat16/float16/внимание,
`python scripts/bench_llm.py` измерит разбор промпта и ток/с (для сравнения моделей: скачайте
`python scripts/download_models.py --llm-repo unsloth/Qwen3-4B-Instruct-2507-GGUF` и запустите bench с `--repo` и `--pattern`).
Если RTF останется выше 1, следующий шаг — более быстрый русский синтезатор для коротких реплик.

## Архитектура

```
Микрофон ─► Silero VAD ─► faster-whisper (ASR) ─► поиск имени «Кику» ─┐
                                                                       ▼
                                  ┌───────────── Агент (цикл) ◄── память: SQLite+FTS5
   Qwen3-TTS ◄─ фразы ◄───────────┤   LLM (GGUF, llama-cpp-python)        факты → системный промпт
   (динамик)                      │   ответ = JSON {tool, args, say}
                                  ▼
                        Реестр инструментов ──► политика путей, белый список приложений,
                        (open_folder, create_file,   подтверждения, журнал audit.jsonl
                         launch_app, tasks, ...)
```

Ключевые решения:

* **Быстрый путь (router).** Типовые команды выполняются без LLM: это мгновенно и предсказуемо.
  Не распознанное уходит к модели.
* **Один вызов модели на команду.** Модель возвращает список действий (до четырёх) и фразу; второй вызов нужен
  только если действию нужен результат (поиск, список) или оно закончилось ошибкой.
* **Один агент + инструменты, а не «стая агентов».** Небольшие локальные модели плохо держат длинные цепочки,
  поэтому «мультиагентность» вводим точечно позже (суб-агент кода, суб-агент экрана).
* **JSON-ответ с принудительной грамматикой.** Модель обязана вернуть `{"actions":[{"tool":..., "args":...}], "say":...}`,
  а имя инструмента ограничено списком (`enum`). Это надёжнее, чем встроенный tool-calling шаблонов малых моделей.
* **Фраза `say` озвучивается сразу** (пока выполняются действия), реплика синтезируется целиком и играет одним куском,
  готовые фразы кэшируются на диск.
* **Полудуплекс:** пока Кику говорит, микрофон закрыт. Перебивать её голосом пока нельзя.
* Имя «Кику» ищется в тексте распознавания (нечётко). После ответа ещё `wake.conversation_window_sec` секунд
  (по умолчанию 25) можно говорить без имени; 0 — имя нужно в каждой команде.

## Установка (Windows 10/11, PowerShell)

Нужны: Python **3.12**, Git, свежий драйвер NVIDIA. Диск: ~30 ГБ под модели. ОЗУ: ~22–25 ГБ в работе.

```powershell
git clone <ваш-репозиторий> kiku; cd kiku
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1

# 1. PyTorch под вашу CUDA (команду подберите на pytorch.org; пример для CUDA 12.4):
pip install torch --index-url https://download.pytorch.org/whl/cu124

# 2. Ядро (текстовый режим)
pip install -r requirements.txt
```

Если `llama-cpp-python` не собирается (нет компилятора C++), поставьте готовое колесо:
`pip install llama-cpp-python --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu`
(для CUDA — `.../whl/cu124`). Актуальность индексов сверьте в репозитории llama-cpp-python.

```powershell
# 3. Голос и окно
pip install -r requirements-voice.txt
pip install -r requirements-gui.txt

# 4. Модели (один раз, нужен интернет). Языковая модель ~18 ГБ.
python scripts/download_models.py --with-design

# 5. Придумать голос Кику (один раз; на CPU может занять несколько минут)
python scripts/design_voice.py
#   ...или положите свою запись 3–10 с в voices/kiku_ref.wav и её дословный текст в voices/kiku_ref.txt
```

## Запуск — рекомендую по ступеням

```powershell
python scripts/check_env.py                    # -1. что видят torch/CUDA, llama.cpp, микрофон
python -m unittest discover -s tests -v        # 0. ядро без моделей: должно быть OK

python -m kiku chat --dry-run                  # 1. LLM + инструменты, ничего реально не выполняется
python -m kiku chat                            # 2. то же, но по-настоящему
python -m kiku chat --tts                      # 3. + голос Кику
python -m kiku voice                           # 4. полный голосовой режим в консоли
python -m kiku gui                             # 5. окно с Кику (то, чем вы будете пользоваться)
```

Если что-то работает медленно — запускайте с `-v` и смотрите замеры: `LLM: N ток. за X с`, `TTS: … RTF`,
а в голосовом режиме после каждой команды печатается `[время] распознавание · агент · дозвучка`. По ним видно, что именно тормозит.
Если что-то не стартует — добавьте `-v`: увидите сырые ответы модели и замеры скорости
(`LLM: … ток/с`, `TTS: … RTF`; RTF меньше 1.0 — озвучка быстрее реального времени).
Первая ступень проверяет самое важное: понимает ли выбранная модель системный промпт и формат JSON.

Веб-интерфейс (экспериментально): `pip install -r requirements-web.txt`, затем `python -m kiku web --tts`
и откройте http://127.0.0.1:8765.

## Настройка (`config.yaml`)

* `router.enabled` — быстрые команды без LLM. `windows.aliases` — разговорные названия окон («вс код», «хром»).
* `wake.conversation_window_sec` — сколько секунд после ответа Кику слушает без имени (25 по умолчанию); 0 — имя нужно всегда.
* `tts.max_spoken_chars`, `tts.prewarm` — сколько озвучивать и заранее ли готовить типовые фразы. `gui.*` — размер окна.
* `tts.cache`, `tts.chunk_chars` — кэш готовых фраз и размер куска озвучки.
* `security.allowed_roots` — папки, внутри которых Кику вообще может что-то делать.
* `apps` — белый список приложений. Для CS2 уже есть `steam://rungameid/730`. Добавляйте свои.
* `llm.repo_id / file_pattern` — модель. Закомментированы варианты полегче (Qwen3-4B) и новее (Qwen3.6-35B-A3B).
* `llm.n_gpu_layers` — сколько слоёв LLM класть в видеопамять. По умолчанию 0: 4 ГБ отданы под ASR и TTS.
* `asr.device`, `tts.device` — `cuda`/`cpu`. Если не хватает VRAM, переведите ASR на `cpu`.
* `tts.mode` — `clone` (голос из `voices/`) или `custom` (готовый тембр без подготовки).
* `security.offline: true` — после скачивания моделей сетевые обращения Hugging Face запрещены.

## Как добавить инструмент

Инструмент — обычная функция. Сигнатура сама попадёт в системный промпт, типы аргументов приводятся автоматически.
Добавьте в `register_system_tools` (или создайте новый модуль и зарегистрируйте в `app.py`):

```python
@reg.tool("lock_screen", "Заблокировать компьютер.")
def lock_screen() -> str:
    if ctx.dry_run:
        return "[dry-run] заблокировала бы экран"
    if not ctx.confirm("Заблокировать компьютер?"):      # подтверждение хозяина
        raise ToolError("хозяин не подтвердил")
    import ctypes; ctypes.windll.user32.LockWorkStation()
    return "экран заблокирован"
```

Правила: возвращайте короткие данные; ожидаемые ошибки — через `ToolError`; всё опасное — через `ctx.confirm`;
не используйте `from __future__ import annotations` в файлах с инструментами.

## Безопасность

Подробно — `docs/SECURITY.md`. Коротко: Кику не имеет инструмента «выполнить команду», не читает содержимое
файлов, работает только в разрешённых папках, запускает только приложения из белого списка, не создаёт
исполняемые файлы и скрипты, перезапись/удаление памяти требует голосового «да», каждое действие пишется
в `data/audit.jsonl`. Веб-интерфейс слушает только `127.0.0.1` и проверяет `Origin`.

## Docker — почему пока не включён

Контейнер Linux не может открывать папки и запускать приложения **на вашем Windows**, а проброс микрофона и
звука в контейнер на Windows — отдельная боль. Поэтому v0.1 ставится нативно. Для «запустил контейнер — работает»
разумная схема такая: в контейнере живут «мозги» (LLM, память, агент, HTTP API), а на Windows — маленький
«исполнитель» с теми же проверками безопасности, который выполняет разрешённые инструменты. Код уже разделён так,
чтобы это можно было сделать следующим шагом (инструменты изолированы за `ToolRegistry`).

## Аватар

В `ui/web.py` + `ui/static/index.html` есть задел: сервер шлёт события `state` (idle/thinking/speaking), `say`
и `tool`, а страница показывает анимированный круг. Сюда подключается Live2D/VRM. Подробности и варианты —
в `docs/ARCHITECTURE.md` (раздел «Аватар»).

## Дорожная карта

1. Вы запускаете ступени 0–4 и присылаете вывод ошибок; я чиню.
2. Перебивание голосом (barge-in) и настоящий wake word (openWakeWord, свой «Кику»).
3. Аватар Live2D в веб-интерфейсе, режим «питомец на рабочем столе».
4. Разделение «мозги/исполнитель» + Docker.
5. RAG по содержимому выбранных папок (с защитой от инъекций через документы).
6. Суб-агент экрана (локальная VLM) и управление интерфейсом: «клавиатура прежде всего», проверка результата.

## Известные риски

* Если TTS пишет, что CUDA недоступна, значит, в окружении стоит torch без CUDA: переустановите по шагу 1 установки.
* Нейросети не запускались: возможны несовпадения версий API (`qwen-tts`, `llama-cpp-python`, `faster-whisper`).
* 4 ГБ VRAM — впритык для ASR и TTS одновременно. Если будет `CUDA out of memory`: `asr.device: cpu` или модель `small`.
* `faster-whisper` на GPU под Windows может требовать библиотек CUDA 12/cuDNN 9 (`pip install nvidia-cublas-cu12 nvidia-cudnn-cu12`).
* Русский — самый слабый из десяти языков Qwen3-TTS по ошибкам произношения: возможны неверные ударения.
* Новые архитектуры LLM (Qwen3.5/3.6) могут быть не поддержаны вашей версией `llama-cpp-python`.
* Решение об «имени в тексте» может ложно срабатывать на похожие слова; настраивается в `wake.fuzzy_ratio`.
